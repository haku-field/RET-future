# Migration Paths

This document describes **non-binding migration considerations**
from **RET-future** to other contexts.

Migration is **not defined here**.
Only boundaries are.

---

## No Internal Migration

RET-future defines **no internal migration path** into RET.

- No condition becomes a requirement
- No evaluation becomes a proposal
- No feasibility becomes authorization

All migration decisions occur elsewhere.

---

## External Decision Requirement

Any movement of material from RET-future requires:

- An external decision process
- Explicit re-authoring
- Independent justification

Copying content verbatim is insufficient.

---

## Transformation Requirement

If RET-future material is reused:

- It must be transformed
- It must be re-scoped
- It must lose its provisional status

Untransformed reuse is invalid.

---

## Non-Guarantee Clause

Presence of a condition in RET-future does **not** guarantee:

- Technical feasibility
- Ethical acceptability
- Structural safety
- Long-term stability

Migration carries full responsibility externally.

---

## Summary

RET-future provides:

- Conditions
- Boundaries
- Failure markers

It does not provide paths.

If a path appears obvious,
it was assumed—not defined.
